Prompt 1 (Claude Code):
"check the correctness of the implementation for each task and ebnf, its' strict following of the week 6 practice instruction file. grammar.ebnf is a week5 grammar file, compiler.py is a week5 compiler, task 1 and task 2 are files with task 1 & 2 for week 6. bypass file edit approving, auto approve every file change, but change only task1, task2, week6 ebnf, week6compiler. don't send me the refactored code, only state with bulleted list the mistakes made before and what you changed."

Summary of the answer:
None of the generated week 6 files could compile the PDF's own example programs, and week6compiler.py also broke ordinary week 5 programs. Checked with lli: the PDF examples now print true, 55, 28 and 36; 38 week 5 error programs give the same messages and line:col as compiler.py (except i32 a{1, 2}, where ',' is now a real token); 38 week 6 error programs are reported at the right line.
- week6grammar.ebnf:
  - fn used ":" instead of ":=". Fixed.
  - decl allowed only one item in {}. It is now "{" init { "," init } "}" with init ::= expr | "{" init { "," init } "}" for the additional task.
  - factor, assign, field and call were rewritten to match the PDF.
- Shared mistakes in task1.py, task2.py and week6compiler.py:
  - "Point p{10, 20}" didn't parse: a declaration was only recognised when the type was followed by mut or {, never by a name. The same check turned x{5} into a declaration and changed the week 5 error.
  - Whole-object := wasn't checked for mut on every field at every depth.
  - Structs were accepted in p + 1, p == q and a top-level exit p, which crashed or produced invalid IR.
  - A struct containing itself had no clear error, and struct or fn after exit was accepted.
  - Week 5 regressions: different messages or positions for i32 x{5 6}, for if/while conditions, for parse_factor at end of line, and for a missing :=.
- task1.py: fields were filled with insertvalue. They are now written through gep by field index, into an alloca of the named struct type.
- task2.py and week6compiler.py (functions):
  - "fn f := (...)" didn't parse (the parser expected a lone ':'), and a lone ':' lost its week 5 error.
  - Calling a function declared further down crashed. All signatures are now declared first, then the bodies are generated.
  - A body without a final exit was accepted and produced invalid IR.
  - Unknown parameter or result types caused a Python KeyError; truncated input like "fn f := (i32" raised IndexError.
  - A body could redeclare a parameter.
  - Some error messages were unclear.
- week6compiler.py (task 3 and additional task):
  - Every built-in declaration (i32 x{5}) failed, so even week 5 programs stopped compiling.
  - Copying a whole object (Point q{p}) broke.
  - Structs were literal types instead of named %"Point" = type {i32, i32}.
  - i32 arguments for i64 parameters produced invalid IR: the call read the parameter's name instead of its type, so no sext was emitted.
  - Field-write errors now point at the link that is const or unknown.
  - Inner {} is built with insertvalue; a {} for a built-in field, or with the wrong count, is reported at that {.
- week6compiler.py was rewritten on top of the week 5 compiler. task2.py is everything except . field access and nested {}; task1.py is the same without functions and calls. All three are readable, have no comments, keep --ast and prefix user functions with fn_ in the IR.
